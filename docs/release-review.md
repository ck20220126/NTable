# NTable release 审查与整改

审查日期：2026-10-03。范围：当前整个项目，包括任务开始时已有的未提交修改。基线 HEAD 为 `8915114`，工作分支为 `main`。按 Code Review 的 Standards / Spec 双轴分别审查，再集中整改并进行隔离复审。没有将旧架构草案的远程分页、服务端查询或业务编辑器当作当前组件必需功能。

## Standards

初轮 6 项实质问题均已整改，最严重的是表格嵌入业务 form 后非提交按钮会提交表单，以及无 ID 筛选条件被同时修改/删除。未以纯代码气味或风格偏好做大规模重构。

| 问题 | 整改结果 |
| --- | --- |
| 原生控件默认提交 form | 表格、菜单、选择器、树按钮均使用 button 类型；SSR 与真实宿主确认 |
| 无 ID 条件共用定位 | 按独立索引操作，使用本地行 key，编辑/删除不影响其他规则 |
| 缓存遗漏 getSubRows | rows、fields、getter 身份变化时全部失效 |
| 缓存无限保留历史数据 | 仅当前数据源，最多保留 8 份投影 |
| 全选仅比较数量 | 按可见 ID 交集计算全选/部分选择；仅切换可见集合；清理已删除记录 |
| 核心记录操作无键盘入口 | 可聚焦行使用 Enter 打开；焦点内显示选择控件 |

release 工程补充：提供 ESM、声明、独立局部 CSS 与包 exports；React 由宿主提供；演示和 Sites 不进入库包；移除未使用的直接依赖并把演示 Dialog 移到开发依赖；同步 npm/pnpm 锁。CSS 的主题、原生控件重置、动画和 portal 规则均限于组件作用域。缺少新增/删除/搜索回调时隐藏对应入口。公开操作符与排序方向为联合类型，记录字段值使用 unknown。

指针交互补充：列拖拽、冻结拖拽与列宽拖拽提供取消及卸载清理；取消调整不持久化；视图切换关闭旧字段菜单。演示层修复存储失败、非法视图、数字零/空值与子记录空选择值，记录编辑器使用现有 Radix Dialog 管理焦点。

## Spec

初轮 3 项契约问题均已整改：选择状态、getSubRows 更新、合法无 ID 条件。与 Standards 的对应问题重叠，不重复计算为独立 bug。最严重的是当前可见记录与已选记录不同却显示全选。

真实消费端验收追加发现并修复：

- 普通固定高度 div 内 NTable 缺少 height:100%，使滚动区为 0；现已按容器高度布局。
- 三个面板使用相同 sibling key，切换视图后重复渲染；现使用各自前缀并添加检查。
- 同视图快速筛选可造成永久加载遮罩；移除独立加载 state，直接根据 useDeferredValue 是否追上受控视图判断。
- 解包严格消费端缺少 Vite ambient 声明时 CSS 导入失败；为 CSS 导出提供独立类型声明，并增加不依赖 Vite 全局类型的消费端检查。
