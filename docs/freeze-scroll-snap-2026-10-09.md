# 横向滚动后的冻结边界吸附修复

## 问题与原因

冻结两列后横向滚动 180px，将手柄拖至屏幕上约 434px 的「当前状态」列右边界，原实现选中第 3 列、将吸附线绘制在约 486px。冻结拖拽沿用未滚动的逻辑列坐标，既未换算普通列的横向偏移，也未排除被冻结前缀遮住的列。

## 修复

- `freezeDropTarget` 使用缓存的列几何计算命中数量与视口内预览位置。冻结区保持固定坐标，普通列扣除当前 `scrollLeft`。
- 忽略被冻结区域完全遮住的普通列；部分可见列按剩余可见区域的中点切换吸附目标。
- 按下原冻结边界保持原数量。左移仍能缩小或取消冻结，最多冻结至倒数第二列。
- 释放时同一预览线切换到目标冻结前缀的最终位置，并沿用已有延迟提交与取消清理机制。

## 验证

`node --test app/tests/column-window.test.mjs` 在旧算法下复现失败：期望 `{count:4,left:434}`，实际 `{count:3,left:486}`；修复后全部 7 项通过。

`npm run verify` 全部 49 项通过，包含演示与库严格类型、构建、Bundler/NodeNext 消费端和打包契约测试。

内置浏览器真实界面使用 Browser Use CDP 鼠标输入复验：

- 横向滚动 180px，原边界与小幅拖动保持 346.234px；拖至 432px 吸附到可见列右边界 434.234px，释放后正确冻结四列。
- 左移至 200px 吸附到 184px，释放后正确冻结一列。
- Escape 取消后仍冻结两列，滚动位置 180px，预览与拖拽状态清理完成。
- 未横向滚动时相同 432px 指针位置仍吸附到 486.234px，释放后冻结三列。
- 浏览器控制台无 error/warn。
